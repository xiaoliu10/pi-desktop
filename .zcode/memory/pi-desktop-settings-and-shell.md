pi-desktop 壳层的几个已排障/已实现机制（2026-09-22）：

- **自动归档"没生效"根因**：归档扫描靠定时器（启动 +15s、每 30min），保存设置后不触发 → 已修：`saveDesktopSettings` handler 里 patch 含 `autoArchive`/`archiveRetentionDays` 时 setTimeout 200ms 跑 `autoArchivePass()`。验证时探针直调 `settings.savePreferences` 不会走该 handler，要手动调 `autoArchivePass()`。探针实测 autoArchive=true + 7 天 → 123 会话归档 100，机制正确。
- **写探针的坑**：① `src/main/index.ts` 导入的是 `node:fs/promises`（无 writeFileSync，静默抛未捕获异常挂住）；② `safePath()` 拒绝路径链上任何符号链接——`/tmp` 是 `/private/tmp` 的链接，沙箱 userData 必须用非链接路径（如 `~/.pi-desktop-probe-sandbox`）；③ 改 src 后必须 `pnpm build`，electron 跑的是 dist；④ `PI_DESKTOP_DATA_DIR` 可重定向 userData，真实配置零风险的沙箱探针模式（输出 JSON + app.exit）。
- **侧栏拖宽**：`src/renderer/replica/shell/ResizeHandle.tsx`（组件 + `usePanelWidth` hook，localStorage 键 `pi.sidebarWidth`/`pi.workbenchWidth`，双击复位），根元素 inline style 覆盖 `--pi-sidebar-width`/`--pi-workbench-width` CSS 变量。手柄悬浮线用 `--pi-text-tertiary`（accent 在浅色主题是纯黑太突兀）。
- **乐观发送反馈三段式**：①点击→prompt 应答：`connecting/pendingPrompt` → ChatView `sending`/`sendingText` 立即渲染半透明用户气泡（`pi-msg--pending`）+ spinner；②**应答→agent_start 空窗**（pi 加载扩展、状态仍 idle，可长达几十秒——用户报"卡很久"的真正根因）：adapter 记 `sentAt: {key, at}`，`sending` 条件覆盖 `sentAt.key===selectedKey && status==='idle'` 及 `status==='starting'`，working 行计时从发送时刻起跳（`sendingAt` prop）；③agent_start 后计时交还执行组，避免双计。`sentAt` 在 run 事件 status∈{running,stopping,error} 时清理。
- **AI 设置并入通用页（2026-09-22）**：独立「AI」导航项已删；内容作为 generalSections 两个分区（AI 默认行为 / Desktop 执行偏好）用 Row select 渲染。store 需 `aiSettings`（settingsSnapshot 加载时带上）；`saveAiSettings` 要传完整 ai 对象（含 revision 冲突检测），失败回滚。onRowControl 的 value 是联合类型（含 boolean），查表前要 `String(value)`；中文显示串与存储值在 handler 里映射（theme 同款做法）。
- **完成态三段式收起（2026-09-22）**：助手回合结束（!liveTurn）后不再按时间顺序交错渲染 segments，而是合并成 [用时行（折叠所有 steps 过程）]+[结论 text 块]。`allSteps` 合并进单个 ExecutionGroup（running=false，showElapsed 显示用时，默认折叠 userOpen=false），`allText` 合并进单个 `pi-msg__answer`。纯文字轮（无 steps）也要显示独立用时行（`pi-chat__elapsed`）——漏掉会让 elapsed 测试红。活动轮（running）保持 chronological 逐步段渲染，过程可见。
- **队列行带图缩略图（2026-09-22）**：`PiRun.queue` item 加 `images?: PiImage[]`（contracts.ts 两处 + shared/pi.ts），发送时乐观队列项带 images；QueueRow 渲染 32px 圆角缩略图（`pi-prompt-queue__thumb`）。pi 的权威 queue_update 只有 text 会覆盖掉 images（乐观阶段才显示），可接受。contracts 需 `export type { PiImage }` re-export，否则 ChatView 拿不到类型。
- **模型配置页显示 provider id（2026-09-22）**：同名供应商（4 个 CCR）靠 id 区分。SettingsPage 左侧列表项 + 右侧详情标题下方加 `pi-models-split__id`（10.5px 等宽小字，单行省略，title 全文），与模型选择列表的编号对齐。
- **working bar 空窗兜底 + auto_retry 接入（2026-09-22）**：「排队后进度不输出」根因不是显示链断流（也不是三段式折叠——turn settle→新轮间隙 running 不掉，tests/live-after-queue.test.ts 证明排队消费后 live 渲染链完好）——session 文件证明 pi 一直在跑（排队消息被正常消费执行），是 CCR 路由两次 `Request timed out.` 造成 ~5 分钟静默窗口，而 working bar 的 `now` 文案在上一步工具完成、新内容未流出时为空，只剩空转菊花。修：① ChatView working bar `now` 改为——retrying 时「正在重试请求（第 N/M 次）」→ 活动工具名 → 默认「正在思考」（之前是空串）；② adapter 新增 `retrying: Record<key,{attempt,max}>` 状态，接 pi 的 `auto_retry_start`（payload 含 attempt/maxAttempts/errorMessage）/`auto_retry_end`，`message_update`/`agent_settled` 兜底清残留；toast 也带重试次数。测试 tests/working-bar-status.test.ts（4 条）+ live-after-queue.test.ts（2 条，验证排队消费后 live 渲染链完好）。
- **队列编辑改召回输入框（ZCode 交互，2026-09-22）**：队列项编辑从行内 input 改为「召回进 composer」——点铅笔把正文+图片附件载回输入框（draftText + contextItems chips，图片可单独删），改完重发即按新内容重新排队。实现：`shared/composer.ts` 新增 `parseContextPrompt`（contextPrompt 的反向：按 `\n\n用户选择的上下文…` 标记拆正文/JSON，JSON 解析回非图片 contextItems，图片走 item.images 单独还原为 image chips，JSON 损坏兜底保留全文）；store 新 `queueRecall(index)` 动作（setDraftText(head) + addContext(recalled) + queueEdit remove + 提示）；QueueRow 删行内编辑态，contracts 加 `onQueueRecall`。注意：召回会覆盖当前输入框草稿。测试 tests/parse-context-prompt.test.ts（4 条往返/兜底）。
- **bash 工具输出剥命令回显（2026-09-22）**：pi 的 bash/run_command 结果存成 `$ <命令>\n<真实 stdout>`（首行命令回显）——「执行输出」区原样显示会露出 `$ tsc ...` 让用户以为"把命令当输出了"。ToolCard 输出渲染剥掉首行 `$ ` 回显（命令已在摘要行）；干净通过（无 stdout）显示「无文本输出。」而非空区块。非 shell 工具不剥。

**Why:** 这些坑（fs/promises、符号链接、stale dist、直调绕过 handler、agent_start 空窗、details 受控状态被冲、完成态漏用时）每个都浪费过一轮排障；机制位置记下来避免重读代码。

**How to apply:** 排查"设置保存了但没效果"类问题先查定时器/事件触发链路，再写主进程沙箱探针端到端验证（记得 build、用非 /tmp 沙箱、用 fs.writeFile）。发送链路 UI 空白优先怀疑 pi 事件边界之间（ack→agent_start）。改渲染结构后跑 pi-execution/optimistic-send 测试确认 elapsed/working 不断言。相关：[[pi-desktop-zcode-ui-parity]]、[[pi-desktop-chat-home-ui]]
