# 自动化任务与工作流：ZCode 参考与 PI Desktop 实现

参考仓库：https://github.com/zai-org/ZCode
参考提交：872ad960de7ec172591f7e1952f7849229f94521

本实现重新编写，复用本项目 pi RPC 内核，不复制 ZCode 的 Agent SDK、账户服务或遥测代码。上游仓库许可证为 Apache-2.0。

## 参考模块

- `packages/shared/src/automation-types.ts`：任务定义、调度、有限次数、执行台账。
- `packages/services/src/session/automationCron.ts`：Cron 只负责计算时间，调度器负责触发。
- `packages/ui/src/settings/AutomationsSection.tsx`、`AutomationEditView.tsx`：卡片列表、模板、编辑、暂停、历史。
- `packages/ui/src/settings/saved-workflows/`：项目／全局工作流、参数、定义、启动与运行历史。
- `packages/shared/src/zcode-protocol/index.ts`：保存工作流的参数和元数据契约。

## 已实现

| 功能 | PI Desktop 行为 |
| --- | --- |
| 自动化入口 | 侧栏自动化 → 任务／工作流 |
| 任务管理 | 创建、编辑、删除、暂停／启用、立即运行、搜索和状态筛选 |
| 时间设置 | 一次性日期；每 N 分钟；每日、工作日、每周、每月、每年预设；五段 Cron |
| 调度限制 | 最多次数、截止时间、同一任务不重叠、最多三个并行自动化 |
| 任务配置 | 本地目录、pi 模型、思考等级、访问模式；执行指令或保存的工作流 |
| 工作流管理 | 描述、适用场景、项目／全局范围、复制、编辑、删除、JSON 导入／导出 |
| 工作流参数 | string、number、boolean、json；必填、默认值；`{{parameter}}` 引用 |
| 步骤 | 添加、删除、排序；同一 pi 会话依次执行；失败后停止 |
| 执行历史 | 手动／定时来源、状态、项目、耗时、步骤、错误、打开对应 pi 会话 |
| 审批 | 遵守 Desktop 访问策略；等待用户操作；从记录打开会话处理；可停止 |
| 重启恢复 | 保留定义和历史；未完成运行标为中断，不自动重复执行 |
| 删除 | 删除定义不删除运行历史或 pi 会话；全部运行记录仍可查看 |

## 执行流程

1. 用户在渲染进程配置定义，经过 preload 的类型化 IPC 送到主进程。
2. 主进程校验目录、参数、调度规则和权限，将定义原子保存。
3. 每 10 秒检查到期任务，先保存下一次触发时间，再创建该次执行记录。
4. 为运行创建独立的 Desktop pi 会话，传入模型与访问模式。
5. 工作流解析参数，将每一步分别作为消息发送到同一会话。
6. 等待真实 `agent_settled` 事件后才开始下一步；模型报错、进程退出或停止时终止后续步骤。
7. 实时回写运行记录。运行结束释放 pi 进程，保留会话文件供查看和续聊。

普通工具返回错误可能由 Agent 自行修复，因此不会把每个工具错误都当成整个工作流失败；模型明确失败或运行进程退出时才终止。

## 调度语义

- 使用本机时区，Cron 为五段格式。固定间隔按原计划时点对齐。
- 调度要求窗口保持打开且电脑唤醒。窗口关闭时暂停调度；重新打开时继续检查。
- 晚于计划一分钟以内可以执行；超过一分钟记录为“已跳过”，不集中补跑。
- 一次性任务错过窗口后结束；循环任务继续计算下一个未来时间。
- 同一个任务已有运行（包括等待审批）时，新触发记录为跳过。
- 立即运行可用于暂停的任务，不改变它的暂停状态；计入总执行次数。
- 保存开启状态就是启用真实调度。默认使用“变更前确认”，不会为了无人值守绕过审批。
- 桌面关闭后的调度、唤醒电脑和系统守护进程不在本版范围。

## 数据与代码

- 定义与台账：Electron `app.getPath('userData')/automations.json`，原子写入，文件权限 0600。
- 限制：最多 20 个任务、100 个工作流、每个工作流 30 步和 30 个参数；运行历史保留最近 500 条及仍在运行的记录。
- pi 会话：继续使用本地 pi 的 `sessions/desktop` 存储，不写入外部 CLI 正在使用的会话。
- 契约：`src/shared/automation.ts`。
- 调度、存储与执行：`src/main/pi/automation-service.ts`。
- IPC：`src/main/index.ts`、`src/preload/index.ts`、`src/shared/pi.ts`。
- 页面：`src/renderer/pi/AutomationsPage.tsx` 与 `automations.css`。

## 与上游的明确差异

这是使用 pi 内核的本地实现，不宣称兼容所有 ZCode 运行时功能：

- 工作流采用声明式 pi 步骤，不能直接执行 ZCode 的 JavaScript 工作流脚本。
- 工作流串行执行，不含上游动态分支、并行 Agent DAG、工作流沙盒和产物协议。
- 不接入 ZCode 云端账户、套餐、闲时算力服务、远程工作区和商业模板接口。
- 不支持从 pi CLI 内直接创建或启动自动化；CLI 能读取所生成的 pi 会话，工作流通过 Desktop 管理和导入／导出。
- 不会因调度失败自动重试可能已经产生副作用的任务；记录错误后由用户决定再运行。
