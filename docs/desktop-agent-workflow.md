# Desktop 自主管理 pi 内核

Desktop 是任务执行入口，pi 是它管理的本地子进程内核。不需要先打开 pi CLI，也没有手动连接步骤。当前仍使用本机安装的 pi 可执行文件；尚未把 pi 运行时打包进安装包。

## 使用流程

1. 启动 Desktop 默认进入任务输入页；新建任务沿用当前项目目录，也可选择其他目录。
2. 发送首条消息时自动启动 pi RPC 进程，使用现有模型、认证和全局扩展配置。没有工作目录时只弹目录选择器。
3. 运行中的会话复用自身进程。工具权限沿用 Desktop 设置，项目扩展默认不额外授权。
4. 启动失败或取消目录选择时保留输入，显示真实错误，允许重试。
5. 点击历史会话后直接输入续接，无需点击“连接”或“在 Desktop 继续”。

## 与 CLI 共享的边界

两端共享原生 JSONL 格式及 pi 会话目录，Desktop 创建的记录位于 agentDir/sessions/desktop。CLI 历史由 Desktop 自动扫描。

当前历史接续采用副本：复制原生记录、生成新的 session ID，并记录 parentSession。这样无需假定 CLI 已停止，也不会与 CLI 同时写同一个 JSONL。它不是两端同时控制同一运行进程，也不是对同一 session ID 的双向追加同步。

## 验证

自动测试覆盖首条消息自动启动、历史接续、运行时复用、取消与失败恢复、启动期间重复提交、新建任务不提前启动进程。全量测试 115 通过、1 项真实 pi 集成测试默认跳过；类型检查及构建通过。已重启实际客户端，确认首页直接输入、历史页带输入框且不再显示连接按钮。
