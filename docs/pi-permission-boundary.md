# Desktop 访问模式

输入框的访问模式菜单控制当前任务；设置 → AI 控制新任务默认值。默认“变更前确认”。底层仍使用本地 pi RPC，与 CLI 共享配置和会话历史；策略由 Desktop 注入的 `extensions/desktop-policy/index.mjs` 执行。

| 模式 | 项目内原生读取 | 普通项目文件 edit/write | bash / MCP / 扩展 / 未知工具 |
| --- | --- | --- | --- |
| 计划模式 | 自动 | 禁止 | 禁止 |
| 变更前确认 | 自动 | 单次确认 | 单次确认 |
| 自动编辑 | 自动 | 自动 | 单次确认 |
| 完全访问 | 自动 | 自动 | 自动 |

读取指原生 read/grep/find/ls；工具必须有 pi 提供的 builtin 来源，同名扩展不享受自动放行。显式目标在项目外、符号链接指向项目外，或目标包含 .env、.git、.pi、.ssh、AGENTS.md 等敏感路径时，计划模式拒绝，其他非完全访问模式询问。该列表是保守启发式，不是完整机密识别或递归内容过滤器。

计划模式减少暴露给模型的工具、追加计划提示、不启动 Desktop MCP bridge，并禁止通过输入斜杠命令执行扩展命令。生成计划后显示“按计划执行”，恢复进入计划前的执行模式，再发送执行提示；直接新建的计划任务默认转到变更前确认。运行中、排队中或等待审批时不能切换模式。切换会在相同会话文件上重启 pi；新 generation 使旧审批失效，启动失败则保持断开，不假装策略已生效。

## 单次审批流程

工具调用 → 核对来源、目标和模式 → 放行 / 拒绝 / 等待确认 → 再核对参数及文件版本 → 执行。

审批展示工作目录、工具、原因和完整参数；写入展示完整文件替换预览，编辑展示替换片段。大于 1 MiB 的旧文件提示在编辑器核对，不生成完整旧文件预览。拒绝、120 秒超时、停止均阻止执行；审批期间目标或参数发生变化则要求工具重新发起。没有永久允许或复用旧审批。模式与工具决策通过 pi custom entry 写入会话，普通对话视图隐藏审计条目；继续历史时不会从这些条目恢复授权。

Desktop 子代理入口继承所选活动任务的模式；无父任务时采用变更前确认。第三方插件自行创建的进程不受此继承机制控制。

## 实际边界

这是工具调用策略，不是操作系统沙箱。项目资源信任由 `--approve` / `--no-approve` 单独控制，仍加载本地受信任的全局扩展。扩展初始化、命令 handler、事件 hook 中直接调用 Node fs/child_process，以及已允许工具内部的二次调用，并不逐个经过这道审批。后续扩展修改工具参数、文件系统并发竞争、硬链接与递归搜索也不能靠目标路径检查提供隔离保证。不能据此安全运行不可信扩展。

若需要对上述行为提供硬隔离，下一阶段应增加操作系统或容器级执行边界，同时管理文件系统和网络权限。当前 UI 明示“作用于工具调用；不是系统沙箱”。

## 验证

`tests/pi-access-policy.test.ts` 覆盖策略矩阵、路径/符号链接、同名扩展、拒绝、参数或文件变化、取消和计划工具集合。
`tests/pi-backend.test.ts` 覆盖切换 generation、会话保留、恢复执行权限、待审批禁止切换及失效回复。
`PI_TEST_EXECUTABLE=/opt/homebrew/bin/pi pnpm exec vitest run tests/pi-integration.test.ts` 使用隔离 pi 配置与本地 SSE 模型验证真实工具执行，不调用外部模型服务。
