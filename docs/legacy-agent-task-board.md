# Coding Agent 开发任务领取板

本文件供用户委派的 Agent 领取任务。整体设计见 [开发流程文档](./legacy-custom-runtime-workflow.md)。当前仅完成代码调查与文档整理，以下实现任务均未领取，也未被本文自动启动。

## 1. 领取与协作约定

1. 先阅读流程文档、目标文件和现有测试，明确当前行为；不要把设计目标当成已实现能力。
2. 领取前由协调者确认状态和负责文件，将对应行改为 `进行中` 并填写负责人。共享 Markdown 不提供原子锁，同时领取须由协调者裁定。
3. **你不是唯一在修改代码的 Agent。保留其他人的改动，不要重置、覆盖或回退无关文件。** 当前仓库已有大量未提交实现，不能将全部未跟踪文件当作自己的新增内容。
4. 只修改领取任务列出的负责文件。需要跨范围修改时，先向协调者提出具体文件和原因；共享协议优先由指定任务修改，再让依赖任务接入。
5. 完成前运行任务对应测试和类型检查。交付时列出修改文件、行为变化、测试命令与结果、剩余问题，不以“代码已写完”代替验收。
6. 没有真实模型凭据时，使用可控假 Provider 或本地 HTTP 测试服务，不索要或读取用户无关凭据；明确区分模拟验证与真实模型验证。
7. 负责人将状态改为 `待验收`，由协调者复核后改为 `完成`。发现阻塞则记录依赖和下一步，不能假装通过。

推荐状态：`待领取` → `进行中` → `待验收` → `完成`；无法继续时为 `阻塞`。

## 3. 任务卡

### A01：Agent 多轮循环、消息配对和流式结束协议

**目的：** 一条用户消息能触发多轮模型请求，模型在读取真实工具结果后继续编辑、验证并总结。

**负责文件：** `src/main/agent/runtime.ts`、`src/main/agent/prompt.ts`、`src/shared/types.ts`；新增 `tests/runtime.test.ts`，必要时调整 `tests/agent.test.ts` 中的消息转换测试。

**实现内容：**

- 区分用户队列循环与单条任务内部的 Agent 步骤循环；落实 `MAX_STEPS`。
- 每批工具执行结束后，把调用与结果加入下一次模型请求。
- 对未知工具、无效 JSON、非对象参数和工具异常保存可配对的失败结果。
- 保持不同模型响应之间的工具批次边界，避免历史转换错误合并多次响应。
- 定义并发出明确的流式消息结束事件，正常、纯工具、异常、中断路径都需收尾；由 A05 完成界面消费。
- 为测试提供最小必要的 Provider 注入点，避免把生产运行时改成测试专用实现。

**验收：** 假 Provider 完成“读文件 → 修改 → 测试 → 总结”；下一次请求包含上一轮结果；工具失败可反馈给模型；达到上限明确停止；模型无工具调用时正常退出；所有分支都有消息结束信号。

**交付给下游：** 记录步骤循环接口、结束事件格式、测试注入方式。不要在此任务顺手重写权限和命令执行。

### A02：文件工具参数与路径边界

**目的：** 文件工具对输入错误和符号链接越界给出可解释的拒绝。

**负责文件：** `src/main/agent/tools.ts` 中的文件工具与路径辅助函数；新增 `tests/tools.test.ts`。不改 `run_command` 的生命周期，留给 A04。

**实现内容：**

- 校验文件路径、文本参数、行号、行数等输入；拒绝空替换目标等模糊操作。
- 对已有路径解析真实路径；创建新文件时验证最近存在的父目录，阻止通过符号链接读写项目外文件。
- 测试项目根目录本身为符号链接的情况，合理区分正常路径与逃逸路径。
- 限制读取和输出规模，避免先无条件读取巨大文件才截断展示。
- 文档中说明仍存在的边界，例如这些检查不等价于操作系统沙箱。

**验收：** 普通目录读写可用；`../` 越界、外部符号链接和链接目录下新建文件被拒绝；参数错误不改变文件；文本精确替换保留现有语义。

### A03：Provider 流式协议异常处理

**目的：** 网络响应完整与否、服务端错误和工具参数分片均有明确处理。

**负责文件：** `src/main/providers/base.ts`、`openai.ts`、`anthropic.ts`、`tests/providers.test.ts`。

**实现内容：**

- 检查 SSE 分片、UTF-8 跨块、CRLF、事件边界与响应尾部处理。
- 处理 HTTP 错误以及 HTTP 200 中的服务端错误事件。
- 区分正常完成与异常断流；未完整完成的工具请求不能当作可执行结果。
- 确保取消时释放读取资源；正常完成的响应只产生一次结束信号。
- 覆盖多个工具调用交错分片；错误日志避免泄露 Key 或其他鉴权信息。

**验收：** 文本和工具调用跨网络块可正确恢复；错误事件不被静默当作成功；取消和断流不会继续输出可执行工具调用；现有协议测试继续通过。

**接口约定：** 尽量保持 `ChatProvider`、`ChatRequest` 和 `StreamChunk` 的现有接口；如需改变，先与 A01 协调。

### A04：会话队列、中断与权限生命周期

**目的：** 同一会话串行处理任务，多会话之间的运行与停止相互隔离。

**负责文件：** `src/main/agent/runtime.ts`、`permissions.ts`、`tools.ts`、`src/main/index.ts`；扩展 `tests/runtime.test.ts`，新增 `tests/lifecycle.test.ts`。开始前接收 A01、A02 的交付。

**实现内容：**

- 明确排队消息的入库、展示与开始执行时机，不让后续输入提前进入当前任务上下文。
- 中断清空尚未开始的队列并记录原因；停止后不能启动新的模型步骤。
- 权限请求按会话和运行绑定；停止 A 不取消 B 的权限等待。
- 将取消信号传入命令执行，处理子进程终止、监听器和超时清理。
- 用户刚批准权限后仍要检查取消状态，防止取消与批准竞争导致意外执行。
- 完成、失败、取消均清理运行注册；删除正在运行的会话或项目时明确处理生命周期。

**验收：** 两条任务依次且各执行一次；停止后队列不运行；等待权限和长命令都可取消；并行会话不互相取消；取消后发送新任务可以正常开始。进程树终止需写明实际验证平台。

**交付给下游：** 状态含义、权限取消机制、队列语义、删除运行中数据的规则。

### A05：界面运行状态、会话切换和 Plan 继续执行

**目的：** 让界面准确反映宿主状态，并完成可用的计划批准流程。

**负责文件：** `src/renderer/store.ts`、`src/renderer/components/ChatView.tsx`、`Composer.tsx`、`PermissionDialog.tsx`、`src/renderer/i18n.ts`、`src/main/index.ts`；必要时调整 `src/shared/api.ts` 与 `src/preload/index.ts`，新增 `tests/renderer-state.test.ts`。

**实现内容：**

- 消费 A01 的流式结束事件，移除纯工具响应及失败后遗留的占位。
- 按会话保存或恢复流式状态与权限请求，避免切换会话后丢失审批入口。
- 处理异步加载竞争：较早发出的加载结果不能覆盖用户后来选中的会话。
- Plan 批准前验证有可批准的计划；批准后自动继续一次，禁止重复点击启动重复任务。
- 明确计划与批准标记的关系；模式切换或计划变化时不能错误沿用旧批准。
- 显示队列长度及取消后的状态，统一中英文文案。

**验收：** 切换会话后可继续审批；任务结束不残留加载动画；Plan 批准后启动执行且只启动一次；发送、排队、停止和错误状态与宿主一致。

### A06：会话存储恢复与配置写入可靠性

**目的：** 一条损坏记录不能使整段历史消失，配置写入中断不应留下半个 JSON 文件。

**负责文件：** `src/main/store.ts`，可新增同目录下的存储辅助模块；新增 `tests/store.test.ts`。

**实现内容：**

- 逐行读取 JSONL，保留有效历史，对损坏行提供可观测的诊断，避免静默吞掉整份数据。
- 区分文件不存在、格式损坏和权限错误；加载失败不能无提示地当作空数据覆盖。
- 对 JSON 配置使用同目录临时文件与原子替换，处理失败后的清理。
- 校验持久化入口使用的项目和会话标识，避免将外部输入直接当作任意磁盘路径。
- 保持已有有效数据可读，避免不必要的格式迁移。

**验收：** 空文件、有效历史、损坏尾行和中间损坏行都有测试；保留可恢复事件；写入失败时原文件仍可读；临时目录测试不触及用户真实数据。

### A07：无 Key 的本地兼容模型接入

**目的：** 让 Ollama、LM Studio 或测试服务等无需鉴权的兼容接口可以使用。

**负责文件：** `src/main/agent/runtime.ts`、`src/main/secrets.ts`、`src/renderer/components/SettingsDialog.tsx`；新增 `tests/model-config.test.ts`，扩展 A01 的运行时测试。需等 A05 完成后再修改其负责的公共文案文件。

**实现内容：**

- 取消运行时对所有提供商统一要求 Key 的判断，按提供商与配置表达实际要求。
- 保留需要鉴权时的清晰错误信息；不把“兼容接口”解释成全部无需鉴权。
- 对 `safeStorage` 不可用时明确拒绝持久化秘密或采用用户可理解的临时策略，不能把 Base64 当作加密。
- 保持界面返回值不包含保存后的明文 Key。

**验收：** 无 Key 的本地兼容请求不带 Authorization；有 Key 时正常携带；主进程解析配置时行为可测；加密不可用的路径有明确反馈；不在日志中打印 Key。

### A08：累计改动审查

**目的：** Review 显示任务产生的实际净变化，而不只是某文件最近一次工具 diff。

**负责文件：** `src/main/store.ts`、`src/main/agent/tools.ts`、`runtime.ts`、`src/shared/diff.ts`、`types.ts`、`src/renderer/components/ReviewPanel.tsx`；必要时调整 `src/renderer/store.ts`，新增 `tests/review.test.ts`。

**实现内容：**

- 先确定并记录基线策略：Git 工作区基线或按会话维护文件快照。
- 同一文件多次编辑后，计算初始状态到当前状态的净变化。
- 识别新建、删除、还原和命令产生的改动。
- 在已有用户改动和多个会话编辑同一文件时明确归属限制，不误称能精确归因。
- 为大文件、二进制文件和非 Git 目录定义展示策略。

**验收：** 同一文件修改两次可看到两次合并的净变化；完全还原后净差异为空；命令生成的文件能被发现或明确标注不支持范围；不丢弃用户原有修改。

### A09：开发启动顺序与进程清理

**目的：** 首次启动不依赖旧的 `dist` 产物，退出时不遗留开发子进程。

**负责文件：** `scripts/dev.mjs`；必要时调整 `vite.config.ts`，新增 `tests/dev-launcher.test.ts` 或提供等价的可重复验证脚本。不改 `package.json`，需要新增命令时交给 A10 集成。

**实现内容：**

- 等待主进程和 preload 首次编译成功，再启动 Electron。
- 编译失败时停止启动并显示错误；固定 Vite 端口或可靠获取实际端口，避免连接到其他服务。
- 明确主进程代码变更后的重新编译与重启行为。
- 退出、启动失败和收到终止信号时清理全部开发子进程。

**验收：** 没有旧构建产物也能首次启动；TypeScript 错误不会启动旧版 Electron；端口占用给出明确错误；停止后端口与子进程被释放。验证时避免删除用户已有文件。

### A10：无 Key 演示与整体集成验收

**目的：** 提供一个学习者可以重复运行的完整例子，并验证合并后的主流程。

**负责文件：** 新增 `examples/agent-playground/`、`scripts/demo-provider.mjs`、`tests/e2e-agent.test.ts`；维护 `package.json`、`README.md`、`docs/coding-agent-workflow.md` 中的使用和验证说明。

**实现内容：**

- 提供独立练习项目：一个确定性错误、一个测试命令、明确的预期修复结果。
- 提供仅监听本机的 OpenAI 兼容演示服务，清楚标明它是预设脚本响应而非真实智能模型。
- 演示读取 → 申请编辑权限 → 修改 → 请求测试命令 → 收到结果 → 总结的完整链路。
- 使用临时数据和工作目录做集成测试，避免污染真实项目或 Electron 用户数据。
- 验证重新加载历史、权限拒绝、工具错误、中断和步数上限。
- 更新流程文档中的实际完成状态，仍未实现的能力继续标为待实现。

**验收：** 新用户按 README 无需购买模型服务即可复现演示；`typecheck`、测试和构建通过；至少完成一次桌面界面冒烟验证并记录结果；真实模型验证如未执行需明确说明。
